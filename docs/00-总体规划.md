> 生成时间：2026-11-15（v2，用户指正后修订）
> 目标：把简历里的四个项目，在本地变成**可编译、可运行、可端到端验证**的真实代码。

## 0. v2 修订说明（重要）

**v1 的错误**：我基于"本机没预装依赖、没有 gcc"就把方案定成「零外部依赖、纯标准库、自己手写 A2A/MCP 协议」。
这个判断是过度保守的——实测 `goproxy.cn`、`PyPI`、`Maven Central` **全部可达**，而且 A2A / MCP 都有官方 SDK（[A2A SDK 索引](https://github.com/a2aproject/a2a/blob/3303592588e388e62e0f69f701af531d2f4e3991/docs/sdk/index.md)、[MCP SDK 分级](https://modelcontextprotocol.io/docs/2026-07-28/sdk.md)）。自己手写协议层在生产工程里是错误做法：既不合规，也把精力浪费在本该由 SDK 解决的地方。

**v2 原则**：**能引用官方 SDK 就引用，自研只做简历里真正属于你的那部分增值能力。**

分层如下：

```
┌─────────────────────────────────────────────────────────────┐
│  第 3 层：你的项目能力（自研，简历差异化所在）               │
│   · 控制面/数据面分离的配置下发与热更新闭环                  │
│   · Envoy 语义过滤器链 + SSE 不断流的护栏实现                │
│   · 模型网关统一路由 / 优先级调度 / Token 限流 / 协议转换    │
│   · 4 类护栏 + Hook 拦截机制                                 │
│   · OpenAPI→MCP 自动转换引擎（$ref 展开 + 回放执行）         │
│   · 状态/会话/任务/持久化解耦（Sidecar 底座）                │
│   · 全链路 span/指标、多语言企业级 SDK 封装                  │
├─────────────────────────────────────────────────────────────┤
│  第 2 层：官方协议 SDK（直接引用，保证规范合规）             │
│   · A2A: a2a-go/v2 · a2a-sdk(py) · a2a-java                │
│   · MCP: modelcontextprotocol/go-sdk · mcp(py) · java-sdk   │
│   · JSON: jackson-databind (Java) · pydantic (Python)        │
│   · HTTP: net/http (Go) · Starlette/FastAPI (Python)        │
├─────────────────────────────────────────────────────────────┤
│  第 1 层：运行时与基础设施（本机替代）                       │
│   Go 1.26 · JDK 11 · Python 3.12 · 本地文件/内存替代 Redis/DB│
└─────────────────────────────────────────────────────────────┘
```

**环境实测结论**（2026-11-15）：

| 项 | 结果 |
|---|---|
| Go | 1.26.1 windows/amd64，`CGO_ENABLED=0`，goproxy.cn 可用 |
| Java | OpenJDK 11.0.23 + Maven 3.9.9，Maven Central HTTP 200 |
| Python | 3.12.4（Miniconda3），PyPI 可用 |
| 第三方缓存 | 本机几乎为空，但**网络可达可拉取** |
| gcc | 缺失 → 因此**不选 Envoy cgo 插件路线**，用纯 Go 的 net/http 过滤器链对齐其语义 |

## 1. 可行性判断（"完全实现"的准确定义）

你简历里的原型是华为云内部、基于 Istio/Envoy Golang 插件、Spring Cloud、Knative、Redis/MySQL 集群、企业 IAM 的生产系统，还绑定了 26.X/27.X 内部版本。1:1 复刻不现实也无意义。

"完全实现" = **把你做过的每项能力落成可运行代码，协议层用官方 SDK 保证合规，生产依赖替换为等价本地实现**。

| 简历能力 | 本地实现 | 生产原型的替代 |
|---|---|---|
| Envoy Golang 插件（L7 过滤器） | Go `net/http` 过滤器链，**逐阶段对齐** Envoy Filter API 语义（DecodeHeaders/Data、EncodeHeaders/Data、LocalReply、AddEncodedData） | Envoy + cgo 插件 |
| Spring Agent 注册中心 | Java `HttpServer` + Jackson + JSON 文件持久化 | Spring Boot + MySQL |
| 高性能模型网关 | Go 反向代理 + 限流 + 优先级调度 + OpenAI 协议转换 | Envoy + 自研插件 |
| Token 限流 | 内存滑动窗口/令牌桶（接口抽象，可换 Redis） | Redis 集群 |
| MCP 注册中心 + OpenAPI 转换 | 官方 MCP SDK 提供协议，自研 `$ref` 展开/导入/回放 | 内部注册中心 |
| Go 双端 Sidecar | 基于 **a2a-go/v2** 的真实 A2A Server/Client + 自研状态解耦 | microVM 沙箱 |
| Java/Python/Go SDK | **基于官方 A2A SDK 二次封装**企业级能力 | 内部 SDK |
| 可观测 | 结构化 JSON span + 指标 | ClickHouse/ES/Thanos |

**明确不做**：K8s CRD、Istio EnvoyFilter、microVM 隔离、企业 IAM、多租户计费、真实 LLM 推理。见 `05-生产映射与差异.md`。

## 2. 依赖清单（版本由 3 个探针子代理实测后冻结，见 `06-依赖与版本.md`）

| 语言 | 官方/第三方依赖 | 用途 |
|---|---|---|
| Go | `github.com/a2aproject/a2a-go/v2` | A2A 协议、AgentCard/Task、JSON-RPC、SSE、client/server |
| Go | `github.com/modelcontextprotocol/go-sdk/mcp` 或 `mark3labs/mcp-go` | MCP 协议（tools/list、tools/call） |
| Python | `a2a-sdk`、`mcp`、`uvicorn`、`httpx`、`pydantic` | Python SDK 与 Mock LLM / 示例 Agent |
| Java | `jackson-databind`（+ A2A/MCP Java SDK 若 JDK11 可用） | JSON、控制面与注册中心 |
| Java | `com.sun.net.httpserver`（JDK 内置） | 轻量 HTTP 服务 |

> 约束：所有依赖**固定明确版本**写入 `go.mod` / `requirements.txt` / `pom.xml`；
> 构建脚本先 `go mod download` / `pip install -r` / `mvn dependency:resolve`，保证可复现。
> 若某些官方 SDK 要求 JDK 17，则该模块降级为「Jackson 实现协议层」，并在文档中如实标注。

## 5. 协议契约

`01-协议契约.md` 是唯一真相源（冻结版 v1.0 + 补充）。**契约定义的是"行为与字段"**，
实现时：
- **字段/类型/错误码**：优先直接复用官方 SDK 的类型（如 `a2a.Task`、`a2a.AgentCard`），
  我们契约里的同名字段作为**合规基线**；若官方 SDK 字段更全，以官方为准并在 `06-依赖与版本.md` 记录差异。
- **自研部分**：过滤器链、SSE 断流修复、限流、优先级调度、配置热更新、护栏 Hook、
  OpenAPI 转换、状态解耦、SDK 企业级封装 —— 这些官方 SDK 不提供，全部自研。

## 7. 验收标准（26 项，见 `01-协议契约.md` §8）

1. `scripts/build-all.ps1`（含依赖下载）一次编译全部模块，退出码 0
2. `scripts/start-all.ps1` 拉起全部服务，`scripts/smoke-test.ps1` 全绿
3. 端到端链路贯通：SDK → 数据面（鉴权/限流/护栏/trace）→ Sidecar → A2A Agent → 流式返回；SDK → 模型网关 → Mock LLM；OpenAPI → MCP → tools/call；控制面改配置 → 数据面热生效
4. 简历里踩过的坑都有对应正确处理与回归用例：SSE 护栏不掐断流、NDJSON 128KB 单行、冒号路径不 panic、请求对象生命周期、过滤器实例复用、配置纳管覆盖
5. 每个模块 README + 单元测试；`05-生产映射与差异.md` 说明本地/生产对应
6. `06-依赖与版本.md` 记录每个官方 SDK 的精确版本、坐标、实测 API 与差异

## 8. 风险与对策（v2 更新）

| 风险 | 对策 |
|---|---|
| 官方 SDK 要求 JDK 17 / 新版 Go | 探针实测；不兼容则降级并**如实标注**，不假装用了 |
| 官方 SDK 的字段与我们契约不完全一致 | 以官方为准，契约标"合规基线"，差异写入 `06` 文档 |
| MCP SDK 2.x breaking change | 固定明确版本，探针实测 API 后再写业务代码 |
| 依赖拉取失败（网络波动） | vendor 化：`go mod vendor`、`pip download` 到 `vendor/`、Maven 本地仓库缓存；构建脚本支持离线回退 |
| 无 gcc → cgo 不可用 | 不用 Envoy 插件 ABI；过滤器链纯 Go；Python/Java 依赖均为纯轮子或纯 Java |
| 中文 Windows 控制台乱码 | 全部 UTF-8，脚本设 `[Console]::OutputEncoding` |
| 多进程端口冲突 | `config/ports.env` 集中管理，启动脚本先探测 |
| 官方 SDK 自带的冒号路径处理与我们手动解析冲突 | 探针明确官方处理方式；以官方为准，我们的 `ParseRestPath` 作为兼容层/回退 |
