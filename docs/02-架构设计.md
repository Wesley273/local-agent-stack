# 02 · 架构设计

> 与 `01-协议契约.md` 配套：契约定义"是什么"，本文定义"为什么这样拆、请求怎么走、状态放哪"。

---

## 1. 设计目标与约束

| 目标 | 约束 / 取舍 |
|---|---|
| 协议合规 | 直接引用官方 A2A / MCP SDK，不自研协议层 |
| 简历能力可验证 | 过滤器链、SSE 修复、限流、热更新、护栏、OpenAPI 转换、状态解耦全部落成可测代码 |
| 单机可跑 | 无 Docker / K8s / gcc；生产依赖用本地等价实现替换 |
| 可复现 | 依赖版本全部冻结；`build-all.ps1` 一次编译 |
| 不失真 | 明确标注本地 vs 生产的映射与不复刻项（`05`） |

**核心架构决策**：**数据面不解析 A2A 语义**（契约 §0.0）。这是整个设计能同时容纳"官方 SDK 合规轨"和"契约兼容轨"的关键。

## 3. 请求生命周期（一条 A2A 消息）

```
1. SDK  POST /a2a/echo-agent  (X-API-Key, X-Request-Id, X-A2A-Version)
2. 数据面 FilterChain
   DecodeHeaders: AuthFilter    → appId=app-demo，注入 X-App-Id
                  RateLimitFilter → 检查 requests/tokens 配额
                  RouterFilter   → 查 Snapshot.agents["echo-agent"].url
   DecodeData:    InputGuardrail → StopAndBuffer 检查全文
   (流式开始后 ResponseStarted=true)
3. httputil.ReverseProxy 原样转发到 Sidecar（不解析 JSON-RPC 语义）
4. Sidecar 官方 a2asrv.NewJSONRPCHandler → AgentExecutor.Execute
   BeforeTask Hook + 4 类护栏
   yield submitted → working → (User Server NDJSON) → artifact(s) → completed
   官方 SDK 内部 sse.NewWriter 把事件写成 SSE
5. 响应回流
   EncodeHeaders: 标记 ResponseStarted
   EncodeData:    OutputGuardrail 逐块检查
                  命中 → AppendEncodedData("event: error...") + Continue
                  ★ 绝不 LocalReply（§3.4）
                  Obs → span 写入 SpanStore
6. SDK 用 a2a.SSEDecoder 跨 chunk 拼帧，拿到完整事件流 + [DONE]
```

**关键不变量**：
- `ResponseStarted` 之后，过滤器链的 `StopAndReply` 一律被忽略并降级（唯一例外：响应尚未开始的鉴权/限流/输入护栏）。
- 数据面在任何时刻都不把 `SendMessage` 翻译成 `message/send`，反之亦然。
- 所有 span 数值字段非 null；批量写逐条容错。

## 4. 配置热更新闭环（简历"手改被 reconcile 覆盖"的正解）

```
控制面写操作 → revision++ → generatedAt 更新 → 持久化 snapshot.json
                                    │
        数据面每 5s: GET /v1/config (If-None-Match: <current revision>)
                                    │
                   ┌────────────────┴────────────────┐
                304 未变                          200 + 新快照
                不动作                             atomic.Value.Store(new)
                                                   revision 更新
                                    │
                        下一次请求立即用新规则（无需重启）
```

- 数据面**没有**本地运行时配置文件可读（只有 `config/ports.env` 提供地址）。
- `POST /v1/admin/reload` 强制立即拉取。
- `GET /v1/admin/config` 返回脱敏摘要，供 E21 断言 revision 变化。

## 5. 状态归属（谁存什么）

| 状态 | 存放位置 | 生命周期 | 重启后 |
|---|---|---|---|
| Agent 注册 / 策略 / 模型 / 限流规则 | 控制面 `data/control-plane.json` | 永久 | 恢复 |
| MCP 工具 / 已导入 spec | 注册中心 `data/mcp-registry.json` | 永久 | 恢复 |
| Task / Session / Artifact | Sidecar `data/agentmecha.json`（FileStore） | 永久 | **恢复（E25）** |
| 限流窗口 | 数据面内存 `MemoryLimiter` | 进程内 | 重置 |
| Span / 指标 | 数据面内存 `SpanStore`（有界 1000） | 进程内 | 清空 |
| 过滤器实例 | `sync.Pool` | 请求间复用 | — |

Sidecar 的 `StateStore`/`SessionStore` 是**接口**，业务 Agent 只通过接口访问，不直接碰文件——这就是简历里"解耦状态、会话、任务、数据持久化存储"的落地。

## 6. 并发与资源

| 机制 | 实现 | 目的 |
|---|---|---|
| 过滤器复用 | `sync.Pool` + `Reset()` + `OnDestroy()` | 修正 Envoy 每请求新建实例导致 OOM |
| 配置原子替换 | `atomic.Value` | 轮询热更新无锁读 |
| 优先级调度 | 3 层有界 channel（64）+ 3:2:1 加权轮转 | 高优优先，低优不饿死 |
| SpanStore | `RWMutex` + 有界 ring | 逐条容错，防整批失败 |
| 限流 | 每 key 独立 `window.mu` | 滑动窗口精确 |
| HTTP 超时 | chat 30s / embeddings 90s，独立 `http.Client` | 复现并解决 embedding 超时 |

## 7. 失败路径

| 场景 | 行为 | 错误码 |
|---|---|---|
| 无/错 API Key | 立即 401 | `AUTH_REQUIRED` |
| app 无授权 | 403 | `FORBIDDEN` |
| agent/model 不存在 | 404 | `AGENT_NOT_FOUND` / `MODEL_NOT_FOUND` |
| 限流 | 429 + `Retry-After` | `RATE_LIMITED` |
| 输入护栏（响应未开始） | 200 错误信封 | `GUARDRAIL_REJECTED` |
| 输出护栏（流已开始） | SSE `event: error` + `[DONE]`，HTTP 仍 200 | `GUARDRAIL_REJECTED` |
| 下游连接失败 | 502 | `UPSTREAM_ERROR` |
| 下游超时 | 504（流式中为 SSE error 帧） | `UPSTREAM_TIMEOUT` |
| 对端提前关流 | 记录 span，不再写响应 | `STREAM_CLOSED` |

## 9. 部署视图（本地）

`start-all.ps1` 按依赖顺序拉起 8 个进程，每个写 `.pids/<name>.pid` 与 `logs/<name>.*.log`：

```
control-plane(9000) → mcp-registry(9300) → mock-llm(9200)
→ go/java/python agents(9101-9103) → agentmecha(9100) → data-plane(8080)
```

`Wait-Health` 逐个轮询 `/health`，全部 UP 才返回 0。`stop-all.ps1` 按 pid 文件停止。
