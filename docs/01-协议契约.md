# 01 · 共享协议契约（唯一真相源 / 冻结版 v1.0）

> **所有模块必须严格实现本文件**。任何字段、路径、错误码的改动都必须回到这里更新。
> 约定：所有 JSON 使用 UTF-8、无 BOM；时间用 RFC3339 字符串；ID 用字符串；金额/计数用整数。

## 0. 全局约定

### 0.0 协议双轨制（v1.1 重要修订，解决官方 SDK 与契约的差异）

实测（见 `06-依赖与版本.md`）表明官方 `a2a-go/v2 v2.8.0` 与本文档 v1.0 假设有实质差异：

| 契约 v1.0（兼容轨） | 官方 SDK（合规轨） |
|---|---|
| `message/send` | `SendMessage`（PascalCase） |
| `state:"completed"` | `TASK_STATE_COMPLETED` |
| `AgentCard.url` | `SupportedInterfaces []*AgentInterface` |
| 手写 SSE | SDK `iter.Seq2[a2a.Event,error]` yield |
| `POST /tasks/{id}:cancel` | `POST /tasks/{idAndAction}` + `CutSuffix` |

**架构决策（所有模块必须遵守）**：

1. **数据面是治理层 + 透明反向代理，不解析 A2A 协议语义。**
   它只做：鉴权 / 限流 / 护栏 / 路由选择 / trace / 配置热更新，然后把 HTTP 请求**原样转发**给下游。
   因此数据面与协议差异完全解耦，两套方法名都能透传。
2. **Sidecar 与 MCP 注册中心的协议合规由官方 SDK 负责**（A2A：a2a-go/v2；MCP：go-sdk）。
   官方 SDK 的字段名/状态值/方法名即为**合规轨的权威定义**。
3. **兼容轨**（本文档 §1 的字段与 `message/send` 等方法名）保留为：
   - 数据面治理层自己的错误信封、trace、护栏、NDJSON 内部协议、SSE 修复规则的契约；
   - 各服务额外暴露的**简化验证端点**（`/a2a/v1/*` 冒号路径），仅用于 E2E 回归与冒号路径测试。
4. 两者**不互相转换、不互相校验**。E2E 用例里：
   - SDK → 数据面 → Sidecar 官方端点 = 合规轨验证；
   - 直接打 `/a2a/v1/message:send` = 兼容轨 / 冒号路径回归验证。
5. 任何模块不得因为"契约写了 `completed`"就去改写官方 SDK 的 `TASK_STATE_COMPLETED`。

> 这条修订让"引用官方 SDK"和"保留简历里的自研能力"同时成立，且不产生协议冲突。

### 0.2 统一 HTTP 头

| Header | 方向 | 说明 |
|---|---|---|
| `X-Request-Id` | 全链路 | 数据面若无则生成（UUID 无横线），**必须原样透传**给所有下游 |
| `X-A2A-Version` | 请求 | 固定 `1.0`；缺失时服务端按 `1.0` 处理 |
| `A2A-Version` | 请求 | **官方 a2a-go/v2 v2.8.0 实际读取的头**（不带 `X-` 前缀）。缺它官方服务端返回 `-32009 VERSION_NOT_SUPPORTED: requested "0.3", served "1.0"`。数据面透明代理会同时补发两个头，SDK 也应两个都带 |
| `X-App-Id` | 内部 | 鉴权通过后由数据面注入，下游信任该值 |
| `X-API-Key` | 请求 | 调用方凭证（demo 值 `demo-key` → `app-demo`） |
| `X-Trace-Span-Id` | 内部 | 当前 span id |
| `X-Priority` | 请求 | 模型网关优先级，`high` / `normal`（默认）/ `low` |
| `Content-Type` | — | `application/json`；流：`text/event-stream` 或 `application/x-ndjson` |
| `Accept` | 请求 | 流式请求须带 `text/event-stream` |

### 0.3 统一错误信封（所有模块一致）

```json
{
  "error": {
    "code": "AUTH_REQUIRED",
    "message": "missing or invalid X-API-Key",
    "requestId": "9f1c...",
    "httpStatus": 401,
    "detail": {}
  }
}
```

**错误码表（不得自造）**

| code | HTTP | 含义 | 抛出方 |
|---|---|---|---|
| `INVALID_REQUEST` | 400 | JSON 解析失败 / 缺必填字段 | 全部 |
| `AUTH_REQUIRED` | 401 | 缺 `X-API-Key` 或 key 无效 | 数据面 |
| `FORBIDDEN` | 403 | app 未获该 agent/model 授权（grants 不匹配） | 数据面 |
| `AGENT_NOT_FOUND` | 404 | agentId 未在控制面注册或已禁用 | 数据面 |
| `MODEL_NOT_FOUND` | 404 | model 名不存在或全部 backend 不可用 | 数据面 |
| `MCP_TOOL_NOT_FOUND` | 404 | tool 名不存在 | MCP 注册中心 |
| `TASK_NOT_FOUND` | 404 | taskId 不存在 | AgentMecha / Agent |
| `RATE_LIMITED` | 429 | 请求数或 Token 数超限；带 `Retry-After` 头 | 数据面 |
| `GUARDRAIL_REJECTED` | 200* | 护栏拒绝；**流式场景不中断连接**，见 §3.4 | 数据面 / Sidecar |
| `UPSTREAM_ERROR` | 502 | 下游连接失败/超时 | 数据面 |
| `UPSTREAM_TIMEOUT` | 504 | 下游超时 | 数据面 |
| `STREAM_CLOSED` | 200* | 流被对端提前关闭（仅记录，不返回错误响应） | 全部 |
| `INTERNAL_ERROR` | 500 | 未预期异常 | 全部 |

> `*` 流式响应已开始后**禁止**再发 HTTP 错误状态，只能以 SSE `event: error` 帧表达（见 §3.4）。

### 1.4 JSON-RPC 2.0 端点

**主端点**：`POST /a2a/{agentId}`（数据面）；`POST /a2a/{agentId}`（Sidecar 直连时）
`Content-Type: application/json`

请求：
```json
{"jsonrpc":"2.0","id":"req-1","method":"message/send","params":{"message":{"...Message":{}},"configuration":{"blocking":true,"historyLength":10}}}
```

| method | params | 结果 |
|---|---|---|
| `message/send` | `message`, `configuration.blocking` | `Task` 或 `Message` |
| `message/stream` | `message`, `configuration` | **SSE 流**（见 §3.2），首帧为 `TaskStatusUpdateEvent(submitted)` |
| `tasks/get` | `id`, `historyLength` | `Task` |
| `tasks/cancel` | `id` | `Task`（state=`canceled`） |
| `tasks/subscribe` | `id` | **SSE 流**，从当前状态开始推送 |
| `agent/getAuthenticatedExtendedCard` | — | `AgentCard` |

JSON-RPC 错误对象：
```json
{"jsonrpc":"2.0","id":"req-1","error":{"code":-32601,"message":"method not found","data":{"code":"INVALID_REQUEST"}}}
```
`-32700` 解析错误、`-32600` 非法请求、`-32601` 方法不存在、`-32602` 参数无效、`-32603` 内部错误。

### 1.5 REST 冒号路径（**简历中的坑，必须实现**）

A2A 规范路径含冒号，Go 1.26 `net/http.ServeMux` 会 panic：
`panic: parsing "/tasks/{id}:cancel": bad wildcard segment`。

**实现要求**：所有服务不得把冒号路径注册进 `ServeMux`。统一注册前缀 `/a2a/v1/` 一个 handler，
在 handler 内用 `parseRestPath()` 手动解析，支持以下路径：

| Method | Path | 等价 JSON-RPC |
|---|---|---|
| `POST` | `/a2a/v1/message:send` | `message/send` |
| `POST` | `/a2a/v1/message:stream` | `message/stream` |
| `GET` | `/a2a/v1/tasks/{id}` | `tasks/get` |
| `POST` | `/a2a/v1/tasks/{id}:cancel` | `tasks/cancel` |
| `GET` | `/a2a/v1/tasks/{id}:subscribe` | `tasks/subscribe` |
| `GET` | `/a2a/v1/card` | `agent/getAuthenticatedExtendedCard` |

`parseRestPath(path)` 返回 `{resource, id, action}`；`action` 取 `""` / `send` / `stream` / `cancel` / `subscribe`。
单元测试必须包含 `long:100000` 这类含冒号参数、**超长 id**、以及 `%3A` 编码冒号三种情况。

**多 Agent 路由补充**：Sidecar 单进程挂载多个 Agent 服务，统一 URL 形态为
`/a2a/{agentId}`（JSON-RPC）与 `/a2a/{agentId}/v1/...`（REST 冒号路径）。
因此 Sidecar 的 `ServeMux` 只注册**一个** `/a2a/` 前缀 handler，在 handler 内先切出 `agentId`，
再对剩余路径调用 `parseRestPath()`；agentId 不存在返回 `AGENT_NOT_FOUND`。
数据面按 `agentId` 查配置快照的 `agents[].url` 转发（默认全部指向 Sidecar）。

### 1.6 SSE 流事件（`message/stream` / `tasks/subscribe`）

响应头：
```
HTTP/1.1 200 OK
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no
```

**帧格式（严格）**：每个事件形如
```
event: status-update
data: {"jsonrpc":"2.0","id":"req-1","result":{...}}

```
`event:` 行可选；`data:` 行内的 JSON **必须是单行**（不含裸换行）。帧以空行结束。

事件体（A2A 标准）：

`TaskStatusUpdateEvent`
```json
{"kind":"status-update","taskId":"task-1","contextId":"ctx-1","status":{"state":"working","timestamp":"..."},"final":false}
```

`TaskArtifactUpdateEvent`
```json
{"kind":"artifact-update","taskId":"task-1","contextId":"ctx-1","artifact":{"artifactId":"art-1","name":"result","parts":[{"kind":"text","text":"..."}]},"append":false,"lastChunk":true,"final":true}
```

终止序列（`final:true` 后）：
```
data: [DONE]

```

**护栏拒绝必须用 error 帧，不得中断 HTTP 连接**（见 §3.4）：
```
event: error
data: {"error":{"code":"GUARDRAIL_REJECTED","message":"blocked by tool guardrail","requestId":"..."},"final":true}

data: [DONE]

```

### 1.7 NDJSON 流（Sidecar ↔ User Server 内部协议）

`Content-Type: application/x-ndjson`，一行一个 JSON 对象，`\n` 结尾。

| 方向 | 对象 | 关键字段 |
|---|---|---|
| Sidecar → User Server | `{"type":"task","taskId":"...","message":{...},"context":{...}}` | |
| User Server → Sidecar | `{"type":"status","state":"working","progress":0.5}` | |
| User Server → Sidecar | `{"type":"artifact","artifactId":"...","text":"..."}` | **text 可 >64KB** |
| User Server → Sidecar | `{"type":"done","state":"completed"}` | |
| User Server → Sidecar | `{"type":"error","code":"...","message":"..."}` | |

> **硬要求**：读取端**禁止**使用默认 `bufio.Scanner`（`MaxScanTokenSize=64*1024`）。
> 必须使用 `scanner.Buffer(make([]byte, 64*1024), 10*1024*1024)` 或 `bufio.Reader.ReadBytes('\n')`。
> 单元测试必须构造一条 128KB 的单行 artifact，断言不报 `token too long`、不丢数据。

### 2.1 `POST /v1/chat/completions`

请求：
```json
{
  "model": "mock-1",
  "messages": [{"role":"user","content":"hello"}],
  "stream": false,
  "max_tokens": 128,
  "temperature": 0.2

```

非流响应：
```json
{
  "id": "chatcmpl-abc",
  "object": "chat.completion",

  "model": "mock-1",

```

```

```
最后：`data: [DONE]\n\n`。角色帧首帧 `delta:{"role":"assistant"}`。

### 2.2 `POST /v1/embeddings`

```json
{"model":"bge-m3","input":["hello","world"],"encoding_format":"float"}
```
→
```json
{"object":"list","data":[{"object":"embedding","index":0,"embedding":[0.1,0.2,0.3]},{"object":"embedding","index":1,"embedding":[0.2,0.1,0.0]}],"model":"bge-m3","usage":{"prompt_tokens":2,"total_tokens":2}}
```
> 超长输入（>8000 字符）用于复现简历中 `content-length: 124844` 的超时排查场景；
> 网关对 `/v1/embeddings` 必须设置独立的、比 chat 更长的 upstream timeout（见 §2.4）。

### 2.3 `GET /v1/models`

```json
{"object":"list","data":[{"id":"mock-1","object":"model","owned_by":"local","priority":10,"backend":"http://127.0.0.1:9200","enabled":true},{"id":"bge-m3","object":"model","owned_by":"local","priority":5,"backend":"http://127.0.0.1:9200","enabled":true}]}
```

### 2.4 模型网关内部规则（数据面实现）

1. **统一路由**：按 `model` 名或 `model` 前缀从配置快照 `models[]` 选 backend；支持多 backend 按 `weight` 加权轮询。
2. **优先级调度**：`X-Priority: high` 进入高优队列（有界 channel 容量 64），`normal` 默认队列，`low` 低优；调度器按 3:2:1 配额轮转，避免低优饿死。
3. **Token 限流**：滑动窗口计数 `tokensPerMinute`；请求前按 `max_tokens` 预估预扣，响应后用 `usage.total_tokens` 结算回填。超限返回 `RATE_LIMITED` + `Retry-After`。实现必须同时支持"按请求数"和"按 token 数"两个维度。
4. **协议转换**：把 OpenAI 请求转成 backend 可接受的格式；backend 返回非 OpenAI 格式（如 `{"text":"..."}`）时转成标准 OpenAI 响应。转换失败返回 `UPSTREAM_ERROR`，不得静默丢弃。
5. **请求/响应转换 + 安全护栏**：请求体过 `inputGuardrail`（blockedWords / maxPromptChars），响应过 `outputGuardrail`；流式中途命中护栏 → 发 `event: error` 帧后继续 `data: [DONE]`，**不调用 `SendLocalReply`**（§3.4）。
6. **超时**：chat 30s；embeddings 90s（独立配置，对应简历中 embedding 超时排查）；所有超时返回 `UPSTREAM_TIMEOUT`。
7. **调用链/指标**：每个请求产出 span，`llm.tokens.*` 必填整数。

## 3. 数据面过滤器链（对齐 Envoy Golang Filter API 语义）

### 3.1 过滤器接口（Go）

```go
type StreamFilter interface {
    Name() string
    DecodeHeaders(headers HeaderMap, endStream bool) FilterStatus   // 请求头
    DecodeData(buf []byte, endStream bool) FilterStatus              // 请求体（可多次）
    EncodeHeaders(headers HeaderMap, endStream bool) FilterStatus   // 响应头
    EncodeData(buf []byte, endStream bool) FilterStatus             // 响应体 / 流块（可多次）
    OnDestroy(reason DestroyReason)                                 // 生命周期结束，归还资源
}

type FilterStatus int
const (
    Continue      FilterStatus = iota // 继续下一个过滤器
    StopAndBuffer                     // 缓冲，等待完整 body（如护栏检查）
    StopAndReply                      // 直接回错误响应（**仅响应开始前允许**）
    LocalReply                        // 兼容旧名，等价 StopAndReply
)
```

`HeaderMap` 封装大小写不敏感的 header 读写，提供 `Get/Set/Add/Del/Clone`。

### 3.2 过滤器执行顺序（**固定**）

```
Auth → RateLimit → Guardrail(Input) → Router → Transform → Upstream
                                                  ↓ (响应)
Obs ← Guardrail(Output) ← EncodeHeaders ← EncodeData(逐块) ← Upstream
```

| # | 过滤器 | 阶段 | 可产生的错误 |
|---|---|---|---|
| 1 | `AuthFilter` | DecodeHeaders | `AUTH_REQUIRED` / `FORBIDDEN` |
| 2 | `RateLimitFilter` | DecodeHeaders | `RATE_LIMITED` |
| 3 | `InputGuardrailFilter` | DecodeData(StopAndBuffer) | `GUARDRAIL_REJECTED` |
| 4 | `RouterFilter` | DecodeHeaders | `AGENT_NOT_FOUND` / `MODEL_NOT_FOUND` |
| 5 | `TransformFilter` | DecodeData / EncodeData | `UPSTREAM_ERROR` |
| 6 | `ObservabilityFilter` | OnDestroy | — |
| 7 | `OutputGuardrailFilter` | EncodeData | `GUARDRAIL_REJECTED`（流式用 error 帧，见 §3.4） |

### 3.3 过滤器实例复用（**对应简历中 Envoy OOM 坑**）

- 过滤器实例**必须来自 `sync.Pool`**，禁止每请求 `new` 一个带大 buffer 的 filter。
- `OnDestroy` 中 `Reset()` 清空状态后 `Put` 回池。
- 提供 `GET /v1/admin/pool` 暴露 `gets/new/puts` 计数，测试断言 `new` 远小于请求数。
- 无 cgo：本实现以纯 Go 过滤器链替代 Envoy ABI，语义一一对应（见 `05-生产映射与差异.md`）。

### 3.4 `SendLocalReply` 语义与 SSE 断流修复（**核心坑，必须实现**）

**问题**（简历原文）：安全护栏在 `encodeData` 里用 `SendLocalReply` 掐断 SSE，导致
`curl: (18) transfer closed`、`reader.read()` 抛错。根因：HTTP/1.1 一个连接只有一次请求-响应，
流中注入新响应破坏 `Transfer-Encoding: chunked` 边界。

**实现约束**：

```go
// 禁止：在流式响应开始后调用任何会写新 HTTP 状态行的方法
// fw.LocalReply(403, ...)   ← 流式场景禁用

// 正确：向当前 chunk 追加 SSE error 帧，然后 Continue
func (g *OutputGuardrailFilter) EncodeData(buf []byte, end bool) FilterStatus {
    if g.rejected { return Continue }
    if hit(string(buf)) {
        g.rejected = true
        frame := "event: error\ndata: " + jsonLine(guardrailError) + "\n\n" +
                 "data: [DONE]\n\n"
        g.ctx.AppendEncodedData([]byte(frame))   // 等价 AddEncodedData
        // 不写状态行、不发 FIN/RST、不 close
        return Continue                          // 等价 api.Continue
    }
    return Continue
}
```

**三条硬规则**
1. `ResponseStarted=true` 之后，过滤器链**忽略**所有 `StopAndReply` / `LocalReply`，降级为 `AppendEncodedData` + `Continue`，并记 `WARN` 日志。
2. 流式响应必须设 `Content-Type: text/event-stream`、禁用任何中间缓冲（`Flush()` 每帧）、不设 `Content-Length`。
3. 上游超时/断连：发 `event: error` (`UPSTREAM_TIMEOUT` / `STREAM_CLOSED`) + `data: [DONE]`，**不得** `RST`。

**回归测试**（`smoke-test` 必须覆盖）：
- 流式请求命中护栏 → HTTP 状态仍是 200、连接正常关闭、客户端收到 `event: error` 和 `[DONE]`，`curl` 退出码 0（无 `(18)`）
- 非流式请求命中护栏 → 正常返回 200 + `GUARDRAIL_REJECTED` 错误信封（因为没有已开始的流）

### 3.5 配置下发闭环（**对应简历中"手改 DestinationRule 被 agentrun reconcile 覆盖"**）

- 数据面**不得**读本地手写配置文件作为运行时规则来源。
- 启动时 `GET {CP}/v1/config` 拉全量快照，之后每 5s 带 `If-None-Match: <revision>` 轮询；
  revision 变化才热替换 `atomic.Value` 中的 Snapshot。

- 数据面 `/v1/admin/config` 返回当前生效的 revision 与快照摘要（脱敏，不含 key 明文）。

## 5. MCP 协议与注册中心

### 5.1 `POST /mcp`（JSON-RPC 2.0）

| method | params | result |
|---|---|---|
| `initialize` | `protocolVersion`, `capabilities`, `clientInfo` | `{"protocolVersion":"2024-11-05","capabilities":{"tools":{"listChanged":false}},"serverInfo":{"name":"mcp-registry","version":"1.0.0"}}` |
| `tools/list` | `cursor?` | `{"tools":[Tool...],"nextCursor":""}` |
| `tools/call` | `name`, `arguments` | `{"content":[{"type":"text","text":"..."}],"isError":false}` |
| `tools/get` | `name` | `Tool` |
| `ping` | — | `{}` |

`Tool`：
```json
{
  "name": "getUserById",
  "description": "GET /users/{id} — 根据 ID 查询用户",
  "inputSchema": {
    "type": "object",
    "properties": {
      "id": {"type":"string","description":"用户 ID (path)","in":"path","required":true},
      "verbose": {"type":"boolean","description":"是否展开 (query)","in":"query","required":false}
    },
    "required": ["id"]
  },
  "annotations": {"title":"Get user by ID","readOnlyHint":true,"destructiveHint":false,"idempotentHint":true,"openWorldHint":false},
  "source": {"type":"openapi","path":"/users/{id}","method":"get","operationId":"getUserById","baseUrl":"http://api.example.com"}
}
```

### 5.2 OpenAPI → MCP 自动转换（**简历核心能力**）

`POST /registry/import` body：
```json
{"spec": { ...OpenAPI 3.0 文档... }, "baseUrl": "http://127.0.0.1:9200", "source": "petstore", "replace": false}
```

转换规则（**必须实现**）：
1. 遍历 `paths` 的每个 `method`（get/post/put/delete/patch），跳过无 `operationId` 的。
2. `name = operationId`（若重名加 `_get`/`_post` 后缀）。
3. `description = summary || description || "METHOD path"`，拼接 `path` 与 `method`。
4. `inputSchema.properties` 来自：
   - `parameters[]`（`in: path|query|header`），`required` 取参数自身 `required`；path 参数强制 required
   - `requestBody.content["application/json"].schema.properties`（`in: body`）
   - **必须解析 `$ref: "#/components/schemas/X"`**，递归展开；`allOf` 合并；数组/嵌套对象保留
5. `annotations` 由 method 推断：`get`→`readOnlyHint=true`，`delete`→`destructiveHint=true`，`put/get`→`idempotentHint=true`。
6. `source` 记录原始 path/method/baseUrl，供 `tools/call` 回放。
7. 返回 `{"imported":N,"tools":[names...],"skipped":[{"path":..,"method":..,"reason":"no operationId"}]}`。

`tools/call` 执行：用 `source` 构造真实 HTTP 请求（path 参数替换、query/body 拼装），
打到 `baseUrl`（本地指向 Mock LLM 的 `/tools/echo` 端点），返回 `{"content":[{"type":"text","text":<HTTP 响应体>}],"isError":false}`。
HTTP 非 2xx → `isError:true`。

其余端点：`GET /registry/tools`（列出）、`DELETE /registry/tools/{name}`、`GET /registry/specs`（已导入文档列表）、`POST /registry/validate`（只校验不导入）。

### 5.3 数据面代理

`POST /mcp/*` → 反向代理到 `http://127.0.0.1:9300`，走完整过滤器链（鉴权/限流/trace），
响应头追加 `X-Proxied-By: data-plane`。

## 6. 护栏与 Hook（AgentMecha Sidecar）

### 6.1 四类护栏（简历中"工具、指令、数据等 4 类安全护栏"）

| 类型 | 名称 | 检查对象 | 触发 |
|---|---|---|---|
| 1 | `ToolGuardrail` | `tools/call` 的 tool name / A2A 中 `data` part 的 tool 字段 | 命中 `blockedTools` |
| 2 | `PromptGuardrail` | 输入文本（A2A message text / chat prompt） | 命中 `blockedWords` 或超 `maxPromptChars` |
| 3 | `InstructionGuardrail` | `data` part 里的 `instruction` / `system` 字段、JSON-RPC `method` 白名单 | 越权指令或非法 method |
| 4 | `DataGuardrail` | artifact / 文件 part / 输出文本 | 敏感数据模式（如 `sk-` 前缀密钥、超长 base64） |

### 6.2 Hook 机制（对齐 OpenCode Hook）

```go
type HookPoint string
const (
    BeforeTask   HookPoint = "before_task"      // 任务创建前
    BeforeTool   HookPoint = "before_tool"      // 工具调用前
    BeforeModel  HookPoint = "before_model"     // 模型请求前
    AfterModel   HookPoint = "after_model"      // 模型响应后
    AfterTask    HookPoint = "after_task"       // 任务结束后
)

type Hook interface {
    Name() string
    Point() HookPoint
    Handle(ctx *HookContext) HookResult
}
type HookResult struct { Allow bool; Reason string; Modified any }
```

- 任一 Hook `Allow=false` → 拦截；非流式返回 `GUARDRAIL_REJECTED`，流式发 `event: error` 帧（§3.4）。
- Hook 按 `Priority` 升序执行，支持短路。
- 内置 Hook：`BlockedWordsHook`、`BlockedToolsHook`、`AuditLogHook`（记录到 `traces`）、`MaxLengthHook`。
- `GET /admin/hooks` 列出已注册 Hook；`POST /admin/hooks/reload` 重新装载配置。

### 6.3 状态 / 会话 / 任务 / 持久化（**解耦的核心**）

Sidecar 必须通过接口抽象，业务 Agent 不直接碰存储：

```go
type StateStore interface {
    SaveTask(t *Task) error
    GetTask(id string) (*Task, bool)
    UpdateStatus(id string, s TaskStatus) error
    AppendArtifact(id string, a Artifact) error
    ListByContext(ctxId string) []*Task
}
type SessionStore interface {
    Get(ctxId string) (*Session, bool)
    Put(s *Session) error
    AppendHistory(ctxId string, m Message) error
}
```
实现：`FileStore`（JSON 文件，目录 `data/`）+ 内存索引；可选 `MemoryStore`（测试用）。
必须支持：断点续传（`tasks/subscribe` 从当前状态续推）、长任务（>60s）状态不丢、进程重启后从文件恢复。

## 7. SDK 统一接口（Go / Java / Python 三语言对齐）

三语言 SDK 必须提供**同名同语义**的能力（语言惯用命名可微调，但方法对应关系固定）：

| 能力 | Go | Java | Python |
|---|---|---|---|
| 客户端构造 | `NewClient(opts...)` | `new A2AClient.Builder()...build()` | `A2AClient(base_url, api_key=...)` |
| 发现 Agent | `GetAgentCard(ctx)` | `getAgentCard()` | `get_agent_card()` |
| 发消息 | `SendMessage(ctx, msg)` | `sendMessage(Message)` | `send_message(message)` |
| 流式发消息 | `StreamMessage(ctx, msg) <-chan Event` | `streamMessage(Message, Consumer<Event>)` | `stream_message(message)` (generator) |
| 查任务 | `GetTask(ctx, id)` | `getTask(String)` | `get_task(task_id)` |
| 取消任务 | `CancelTask(ctx, id)` | `cancelTask(String)` | `cancel_task(task_id)` |
| 订阅任务 | `Subscribe(ctx, id) <-chan Event` | `subscribe(String, Consumer<Event>)` | `subscribe(task_id)` |
| 模型调用 | `Chat(ctx, req)` | `chat(ChatRequest)` | `chat(**kwargs)` |
| MCP 工具 | `ListTools(ctx)` / `CallTool(ctx, name, args)` | `listTools()` / `callTool(String, Map)` | `list_tools()` / `call_tool(name, **kwargs)` |
| 护栏本地检查 | `CheckGuardrail(text)` | `checkGuardrail(String)` | `check_guardrail(text)` |
| 错误类型 | `A2AError{Code, Message, RequestID}` | `A2AException` | `A2AError` |

SDK 行为要求：
- 自动带 `X-A2A-Version: 1.0`、`X-Request-Id`（本地生成 UUID）、`X-API-Key`
- SSE 解析必须支持**跨 chunk 拼接**（一个 `data:` 帧可能被 TCP 拆成多次读），禁止按单次 `Read` 假设完整帧
- NDJSON 解析同样支持 >64KB 单行
- 超时可配置；`UPSTREAM_TIMEOUT` 映射为语言原生 timeout 异常
- 每个 SDK 自带一个可运行 example，证明能跑通全链路
